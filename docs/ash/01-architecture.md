# Ash phase 2 — Screen-off wake detection and assistant architecture

**Decision:** ship the phone-microphone path first. The user arms a visible, stoppable microphone foreground service (FGS) before locking the phone. One recorder feeds one local sherpa-onnx keyword spotter for **Hey Ash** and **Hello Ash**. On a hit, the same samples feed the existing English command recognizer; no unlock, network call, Bluetooth negotiation or assistant-role lookup is on the wake-to-command path. Screen-off listening is not the same as waking the display or unlocking the phone.

This is a design for the existing Kotlin app, not a claim that Ash already works on a particular handset. Manual invocation without standby capture is the low-power alternative. Default-assistant selection adds system invocation; it is **not** the mechanism that recognizes these two phrases.

## 2. Service contract: consent, capture and default assistant

Use three distinct controls: **Off** (no capture; external invocation may offer setup but cannot re-arm), **Talk only** (explicit user turn, nothing recording between turns), **Listen while screen is off** (explicit continuous local capture, actual route shown). Persist user preference, not a fictitious `running` flag. Require affirmative consent on upgrade before starting Ash standby; do not translate old boot/custom settings into new microphone consent. Expose Turn off in app and notification; Stop task cancels a turn, not the listening preference. Role, contacts, accessibility, Bluetooth and cloud are independently optional.

**FGS path.** From a resumed activity explain purpose, models, battery and route; obtain `RECORD_AUDIO`, verify assets, then while still visible call `ContextCompat.startForegroundService` for `JarvisService`. Promote promptly with `ServiceCompat.startForeground` before model I/O, loading the runtime or opening audio; use the microphone type on API 30+, legacy compatible flags below. Then open and verify the recorder; publish “Listening • phone mic” only on actual capture, distinguish starting, paused, missing model and off. Require `FOREGROUND_SERVICE` and, for target 35 on API 34+, `FOREGROUND_SERVICE_MICROPHONE` in addition to runtime permission. Use an ongoing low-importance, silent channel, private lock-screen visibility, coarse state only, explicit immutable pending intents. No task text/contact in notifications. Ask for `POST_NOTIFICATIONS` on 33+: denial does not legally prevent FGS launch or remove the obligation to supply its notification; the FGS can appear in Active apps rather than the drawer. Ash policy: when drawer controls aren't available, offer Talk only and settings rather than silently enabling standby.

**Assistant path (proposed, same package).** Add the following contract to `app/src/main/AndroidManifest.xml` only in the later integration milestone. Use fully qualified class names in the linked resource; shorthand below refers to new classes under `com.jarvis.assistant.assistant`.

Explicitly set component export flags; export the recognition provider for legitimate recognition clients, never the capture/command FGS. Use the [platform example](https://github.com/aosp-mirror/platform_frameworks_base/blob/android-15.0.0_r1/tests/VoiceInteraction/AndroidManifest.xml) for component relationships, **not** its test permissions. Keep system-facing callbacks small; delegate heavy work to the existing worker/audio owner. Keep one process/arbiter initially, without loading models in idle system callbacks. If a later session UI gets a separate process, use private IPC to the owner, never a second singleton recorder.

The [framework attribute contract](https://github.com/aosp-mirror/platform_frameworks_base/blob/android-15.0.0_r1/core/res/res/values/attrs.xml#L9374-L9383) distinguishes the releases: on API 26–30 the recognition component must actually work as a speech provider; on 31–35 the name is still required but does **not** select the system recognizer. Use `android:exported="false"` for the explicitly system-bound session service (no filter), and `true` for the protected interactor and the recognition-client endpoint. Call `super.onReady()` before using the interactor.

**User selection:** open `Settings.ACTION_MANAGE_DEFAULT_APPS_SETTINGS` from visible onboarding if resolved, otherwise give the manual path Settings → Apps → Default apps → Digital assistant / Assist & voice input (labels vary). API 29+: check `RoleManager.isRoleAvailable(ROLE_ASSISTANT)` and `isRoleHeld` for status. Do **not** rely on `createRequestRoleIntent(ROLE_ASSISTANT)` showing a chooser: [AOSP 35 role configuration](https://android.googlesource.com/platform/packages/modules/Permission/+/android-15.0.0_r1/PermissionController/res/xml/roles.xml#95) sets `requestable="false"`. On all supported APIs recheck `VoiceInteractionService.isActiveService(context, component)` on return/resume; an activity-only holder is not a bound interactor. On API 26–28 use settings and the active-component check without `RoleManager`. No role, denied selection or low-RAM device without service support → keep phone-mic and manual modes. Never write secure settings.

**Invocation:** the system shows a session for supported gestures; home/power/headset mappings depend on the OS, user and hardware. `showSession(args, 0)` is for the **active, ready** interactor on a legitimate user trigger; don't request assist data or screenshots by default. `ACTION_ASSIST` and `ACTION_VOICE_COMMAND` are possible **activity actions**, not broadcasts guaranteed from all earbuds. An exported DEFAULT-category Talk entry may present a visible fallback; ignore extras, require user intent and converge on the same arbiter. Never accept arbitrary commands or re-arm standby via exported intents. No normal media-button interception. Start with keyguard invocation **off**. Advertising it later requires `onLaunchVoiceAssistFromKeyguard()` to start a new redacted show-when-locked activity, not just a session overlay ([callback contract](https://developer.android.com/reference/android/service/voice/VoiceInteractionService#onLaunchVoiceAssistFromKeyguard())). That activity cannot unlock the device.

Android documents a while-in-use exemption for an app providing the active voice interaction service. Check **both** general FGS-start eligibility and current microphone eligibility, not just a manifest declaration or `checkSelfPermission`. For a real system invocation, use an already eligible capture owner; if a new mic FGS cannot legally be started, offer a user-visible Talk activity to start it. No background launches manufactured from a role callback. Role loss ends role-dependent work; a separately, visibly armed capture may continue on its own eligibility. A microphone service is not general authorization to bring another app to the foreground; use visible session/activity or a user-tapped notification for UI actions.

## 3. Screen-off support envelope and recovery

| Class | Contract for Ash |
|---|---|
| **A — Supported, normally reliable** | Once a visible user start, mic permission, notification, models and actual input are established, a microphone FGS can **continue** local recording as the activity leaves and the screen locks. No role or accessibility required. First supported scenario: both phrases followed by a local time query, offline, display still off. Manual Talk does not need continuous capture. |
| **B — Device/policy dependent** | Deep idle duration, CPU scheduling, actual mic priority/silencing, OEM process limits, thermal throttling, available system invocations, wireless routing, and network/TTS latency. Report “not listening” if input is unavailable. No indefinite uptime promise. A downloaded assistant with the role does not acquire the special input-sharing priority documented for **preinstalled** assistants. |
| **C — Hardware/integration dependent** | SoundTrigger/DSP low-power keyphrases need a supported HAL, model, enrollment and OEM/system integration; some headsets detect their vendor's own keyword or invoke a button action. None proves arbitrary Ash phrases can run in the DSP or sleeping earbuds. LE Audio input requires supported phone, stack and headset. Not baseline capabilities. |
| **D — Unsupported/security restricted** | No capturing after permission revocation or sensor privacy mute, no boot-time mic FGS on restricted releases, covert background recorder, force-stop evasion, call-audio interception, unlocking by voice or automation behind a protected screen. No root, privileged audio permissions, silent role changes, fake playback or accessibility keepalive. |

| Device API (app targets 35) | Implementation boundary |
|---|---|
| 26–28 | Notification channel; use foreground start/promotion for ongoing capture. From 28 background-only mic may receive silence; use FGS. Legacy assistant picker and SCO path. |
| 29–30 | RoleManager on 29; recording-policy silencing visible via `AudioRecordingConfiguration.isClientSilenced()` on 29+. At 30 declare/use microphone FGS type; creating a service from background does not automatically give mic access. |
| 31–32 | Background FGS starts generally restricted, even with granted mic permission. Handle `ForegroundServiceStartNotAllowedException` at launch. Mic privacy indicator/toggle; communication-device APIs. No BT discovery needed. |
| 33 | Notification runtime permission, Active apps Stop, LE Audio support on compatible hardware. Respect user stop even when no callback arrives. |
| 34 | Specific microphone FGS permission/type and while-in-use prerequisite checked at creation/promotion (possible `SecurityException`). Mic boot restriction already applies here, **not first at 35**. Catch failure at caller and promotion, tear down and show user recovery. |
| 35 | Additional boot-type restrictions; focus request requires top app or running FGS. Data-sync/media-processing time limits are not an allowance or a six-hour timer for microphone listening. |
| Newer OS, same APK | Test on actual releases against target-35 behavior and all-app changes. No post-35 API reference required by this design. Requalify before raising target SDK. |

**Boot, death and interruptions.** Make reboot notification-only if the user requested a reminder, notifications are allowed and the user has unlocked; otherwise wait for app/assistant invocation. Never start the recorder from `BOOT_COMPLETED`, package upgrade, accessibility connect, scheduled work or a dummy FGS; no direct-boot secrets. System may bind the selected assistant again but that is not consent to record. Choose `START_NOT_STICKY` for the initial design: after actual process death lose the turn and mic lease; the next legal explicit start revalidates consent, permission, installed model version, route and keyguard. No replay of transcripts, queued calls or unfinished UI actions. Swiping the task away, system FGS Stop, process reclamation and Settings Force stop are different events; never use one as a signal to defeat another. New process starts with actual state off; on next visible launch offer re-arm, not “already listening.”

Screen-off ≠ Doze. Doze on a stationary unplugged phone can suspend network, defer jobs/alarms and ignore app wake locks; an FGS is not a general exemption. An active FGS normally keeps the app out of App Standby's idle classification; it doesn't ensure screen-off CPU or mic delivery forever. No wake lock for idle KWS, screen-bright lock, repeating job, exact alarm, watchdog service or routine exemption request. Use bounded active-turn work and monotonic deadlines. Only consider a short timed partial lock around a **measured** active local handoff if needed, release in `finally`; it is not a deep-idle fix. Don't wake the display for a nonvisual command. If the OEM stops Ash, show last known reason when available, normal system battery settings and an explanation of the tradeoff; offer Talk only instead of requiring “unrestricted” battery or disabling protections.

Register recording configuration callback before recording on 29+, route callbacks, permission/privacy state where available, and handle read errors on every supported OS. Detect client silencing, active call/VoIP preemption, sustained all-zero buffers (a symptom, **not** proof of silence policy), `ERROR_DEAD_OBJECT` and missing routed device separately. Yield to calls/other recorders; don't fight a call by changing mode or reopening. Known blocker → `INTERRUPTED`; stay event-driven (call ends, route available, explicit Retry). Use a recorder's unsilenced callback only while still registered/owning it; after releasing it use external availability/foreground retry, not a callback on a dead recorder. Unknown transient device failure → one delayed retry after 0.5 s and one after 2 s, only if same eligible service/consent and not blocked; then release, stop FGS if no user-visible work, require user Retry. Never treat reopening as success before valid routing/capture. Existing `VoiceInput.loop` caps the pause on generic failures, **not** the total number of attempts.

Sources: [FGS start vs while-in-use exemptions](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start), [microphone service type](https://developer.android.com/develop/background-work/services/fgs/service-types#microphone), [Android 15 boot rules](https://developer.android.com/about/versions/15/behavior-changes-15#fgs-boot-completed), [notification denial](https://developer.android.com/develop/ui/views/notifications/notification-permission), [user stopping](https://developer.android.com/develop/background-work/services/fgs/handle-user-stopping), [sharing audio input](https://developer.android.com/media/platform/sharing-audio-input), [Doze and standby](https://developer.android.com/training/monitoring-device-state/doze-standby), [Sound Trigger](https://source.android.com/docs/core/audio/sound-trigger).

## 4. Offline dual-keyword specification

Reuse the open-vocabulary English GigaSpeech 3.3M Zipformer transducer in `WakeModel` (`voice/VoiceInput.kt`): the int8 encoder/decoder/joiner plus the **matching** token table. It decodes allowed token sequences, not a classifier trained solely for the string “Jarvis.” Changing only `@label`, UI copy or a filename would leave the old acoustics in place.

1. In a development workspace unpack the exact `sherpa-onnx-kws-zipformer-gigaspeech-3.3M-2024-01-01` archive named in `WakeModel.URL`, **before** `ModelDownloader.prune` removes the tokenizer. Pin digest/version and review model license. Generate one UTF-8 keyword file; don't ship Python or a second encoder. Example, with `KWS` set to the unpacked model directory and the version-matched sherpa CLI installed:

   ```sh
   printf 'HEY ASH @HEY_ASH\nHELLO ASH @HELLO_ASH\n' > ash-phrases.txt
   sherpa-onnx-cli text2token --tokens "$KWS/tokens.txt" --tokens-type bpe \
     --bpe-model "$KWS/bpe.model" ash-phrases.txt ash-keywords.txt
   ```

2. A read-only application of the repository's unigram scoring algorithm to its `wake-pieces.txt` gave these expected lines. Compare generated output, require each piece to exist in the exact model vocabulary (no unknown tokens), load both entries in **one** `KeywordSpotterConfig.keywordsFile`, and check real hit IDs before accepting. No bare “Ash” entry; no automatic Jarvis aliases. Preserve user's explicit custom phrase as optional additional vocabulary, clearly labeled; do not substitute it for one of the two required phrases, auto-enable old defaults, or admit bare Ash via that slot.

   ```text
   ▁HE Y ▁A SH @HEY_ASH
   ▁HE LL O ▁A SH @HELLO_ASH
   ```

   Vocabulary cross-check against the upstream archive: `HEY ASH` IDs `49 17 6 280`; `HELLO ASH` IDs `49 60 22 6 280`. Tokenizer SHA-256 `c8a2a0129c4ab8e463164c142f82d25649661b122c8cd0b7aab5c9e80b90ad24` identifies **bpe.model**, not the whole archive. `createStream("")` uses file defaults. In [v1.13.8](https://github.com/k2-fsa/sherpa-onnx/blob/v1.13.8/sherpa-onnx/csrc/keyword-spotter-transducer-impl.h) dynamic entries use `/` between encoded rows and are combined with the defaults. Replace the built-in Jarvis rows; adding Ash only as dynamic entries would leave Jarvis active. Cache any custom row outside the read loop.

3. One line per phrase; optional `:boost #threshold` before `@id`. Start from measured Jarvis settings **as trials**, not release thresholds. More boost keeps paths alive; lower threshold typically increases hits **and** false activations. Tune each separately with slow/fast speech, accents, quiet/far-field speech, fan/road/TV/music noise, phone-in-pocket and headset audio. Use `MicGain` with capped gain and route-specific reset/noise-floor learning in idle only; do not gate away soft leading syllables with an amplitude threshold. Hold out speakers and noise sessions from tuning. Fail unsafe settings even if aggregate recall looks good. No guarantee on every accent or on recordings of the real phrase played by a TV; a wake word is not speaker authentication.
4. Preserve the active `VOICE_RECOGNITION` 16 kHz mono PCM path, 100 ms read baseline, 80-bin features and one KWS worker. Keep English ASR initialized once when arming seamless mode; no continuous ASR decoding, cloud audio or LLM in standby. On hit, atomically latch `hitId`, sample sequence and turn; reset/inhibit KWS, preserve the existing ~1.5 s pre-roll and bounded post-hit buffer. Replay into a fresh Kroko stream **once**, in sample order including the hit chunk; continue live from the next sequence, without reopening the mic. Never wait for TTS, UI animation or Bluetooth. If an overrun or route change makes the turn incomplete, discard and request repetition rather than dispatch a suffix. On end clear/overwrite PCM, release per-turn streams, reuse loaded models.
   Jarvis currently retains at most 50 nominal blocks **including** the copied pre-roll, not an extra five seconds after it. Size the bound in samples so short reads do not shrink coverage; declare overrun rather than silently drop. When replay reaches an ASR endpoint, stop feeding that stream before release. Do not decode remaining backlog on a finalized native handle.
5. Map ID to actual spoken prefix; strip only an anchored detected phrase (or known truncated prefix-tail from pre-roll), not every “Ash” or similar-sounding word. Preserve “call Ash”, “type hello Ash” and custom dictation. Update `VoiceInput.clean`, TTS self-wake suppression, `router/Lexicon.kt`, `router/FastCommandRouter.kt`, `router/MemoryIntentParser.kt`, settings prompt and transcripts at the boundary. Do not fuzzy-match “ask/cash” into a short wake word. One hit episode, one final command; no action on isolated hit, partial transcript or echo. Reset decoder state at turn/route boundaries. Suppress any wake prompt while command speech is arriving.
6. If Kroko is missing, unsupported for the language or can't initialize, **do not advertise seamless mode**. Offer model installation, typed input or separately consented one-shot platform recognizer: first obtain release acknowledgement from the local recorder, then prompt when the new input is ready. This path cannot reconstruct the original first word; ask the user to repeat. Never pass pre-roll to the platform/cloud. In local-only mode refuse network-capable ASR or TTS rather than treating an offline preference hint as an assurance.

References: [sherpa keyword format and controls](https://k2-fsa.github.io/sherpa/onnx/kws/index.html), [exact English model and customization workflow](https://k2-fsa.github.io/sherpa/onnx/kws/pretrained_models/index.html#sherpa-onnx-kws-zipformer-gigaspeech-3-3m-2024-01-01-english). Tokenization is not an acoustic validation.

## 5. Microphone ownership, Bluetooth and playback

One process-local capture arbiter; a lease specifies owner, purpose, generation and **observed** input. `VoiceInput` owns the `AudioRecord`; recognizer clients, local KWS, ASR and optional barge-in are consumers/modes, not independent recorders. `CommandListener` gets a mutually exclusive external lease only after release; its termination/cancel must finish before reacquisition. Serialize open/read/close and native decode/release away from the UI; bounded close timeout means error, **not** permission to open a second stream. Activity, VIS, session, accessibility and route callbacks send events only.

| Route | Standby and turn policy |
|---|---|
| Handset / wired / USB | Prefer handset for always-listening unless user picks a verified external input. Enumerate `AudioManager.getDevices(GET_DEVICES_INPUTS)`, select an actual source via `AudioRecord.setPreferredDevice`; a wired headset or USB device may include a mic, headphones may be output-only. Confirm `getRoutedDevice()` on the **running** recorder, observe changes; a preference or headset icon is not proof. |
| Classic BT | A2DP is playback, not a microphone. HFP/SCO off-call may allow mono capture at lower bandwidth and disrupt music fidelity. No always-held SCO by default. API 31+: choose the matching available communication **sink** (`TYPE_BLUETOOTH_SCO`); Android selects the corresponding source. API 26–30: check `isBluetoothScoAvailableOffCall`, register for sticky `ACTION_SCO_AUDIO_STATE_UPDATED` before `startBluetoothSco`, await connected, observe actual input. Legacy codec/path may need 8 kHz mono; resample once to model rate if necessary or fall back. Pair every started SCO request, including failed setup, with `stopBluetoothSco`. Replacement API added at 31; start/stop SCO deprecated at **34**. |
| LE Audio | API 31+ communication selector supports `TYPE_BLE_HEADSET` if exposed; platform LE Audio support from Android 13 on compatible devices. Select actual listed sink for communication, or prefer an exposed LE recording source for direct capture. BLE pairing, hearing-aid output, LC3 capability or two connected buds do not establish a live microphone, duplex quality or standby lifetime. |
| TTS/output | Follow user's current Android media/assistant output (private headset where selected); phone speaker, wired and BT output need not match input. Release any turn-only communication route before high-quality media TTS, await route change/verify where observable. Do not assume a fixed A2DP settle delay. If private output disappears, stop the reply rather than spill it to speaker; require explicit choice before resuming. `AudioTrack` routing is observable while playing, system TTS engine routing is not necessarily observable; suppress sensitive speech on unverified output. |

**Wireless transition.** Track *available → requested → observed → released* per route generation. Register `AudioDeviceCallback` for inventory, and API 31+ `OnCommunicationDeviceChangedListener` before `setCommunicationDevice`; check return and current snapshot, then await matching selection **and** running recorder input with plausible signal. `true` is request acceptance; do not compare source and sink IDs as if identical. Use turn-owned `MODE_IN_COMMUNICATION` only where necessary; never set `MODE_IN_CALL`. Wait up to 3 s initially (tunable on devices). A button-started turn may negotiate then indicate “speak now”; a phone-mic keyword starts its command **on the same route**, even if earbuds are connected. Do not drop syllables switching mid-sentence. Reset gain, echo and pre-roll on input transition. On timeout/rejection/denial, clear own `setCommunicationDevice` with `clearCommunicationDevice()` or release SCO, release own mode request, then verify built-in fallback and visibly/audibly indicate the input. If fallback disallowed or missing, stop. On actual selected-input loss *during* a command, cancel the partial command; start a fresh turn only after route readiness. Ignore removal of unrelated devices and stale timers; SCO-only loss is not proof that the user said “stop”. Unregister every listener on teardown.

**Can the target earbuds listen while idle? Unknown.** No target hardware or isolation test. The default releases the earbud communication link: **a phrase spoken only into an inactive earbud mic may never reach Ash**. Offer phone-mic standby or an OEM-supported headset assistant gesture followed by a ready cue. Offer a separate continuous earbud option only for measured phone/firmware pairs, after explaining drain, audio-quality tradeoff and fallback. If the real route cannot be established, never label it “earbuds listening.” Yunto's [field observations](https://github.com/lovisschmidt/yunto/blob/8bb110a6a11738601ae639dd4bd32eb446326f25/docs/headset-compatibility.md) are not standby qualification.

**Focus is output arbitration, not a mic lock.** No focus for idle detection or model wait. Request `AudioFocusRequest` (26+) for short audible turns, typically `AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK`, with `USAGE_ASSISTANT` / `CONTENT_TYPE_SPEECH`; transient pause where appropriate. Gate *every* output path (`voice/Voice.kt`, `voice/AudioOut.kt`, `voice/SystemVoice.kt`, cached prompts and streamed speech). Failed request: no sound; use visual status. On loss pause/stop output, invalidate stale continuations, abandon the same request on every exit. Never raise music volume, simulate Play or resume a third-party player on cleanup; releasing the focus/route is restoration. On target 35 a top app or running FGS is required to request focus. Normal play/pause presses remain the player's. No permanent Ash `MediaSession`.

## 6. Unified voice state machine

`JarvisService` owns a serialized reducer (main handler is sufficient). Audio thread owns sample order, recorder and native streams. Workers receive immutable turn IDs; they never directly change mic, focus, route or UI. Model loading is single-flight per installed version. Track `userMode`, actual `state`, `generation`, `turnId`, `origin`, route lease, capture owner, pending approval and `effectStarted` separately. TaskBoard may retain background **read-only** work; only one foreground turn can speak/listen/drive the UI. No hidden parallel voice machine in the assistant session.

| State | Entry, events and next state |
|---|---|
| `DISABLED` | No recorder, ring, focus, route lease or mic FGS. Distinguish Off vs Talk-only idle by preference. Authorized Arm + permission/model readiness → `WAKE_LISTENING`; deliberate Talk in enabled mode → `COMMAND_LISTENING`. Missing prerequisites → explain/recover, never report ready. |
| `WAKE_LISTENING` | One verified recorder, local KWS + ring only. First allowed hit or Talk wins single turn → `COMMAND_LISTENING`; duplicate button/session/hit events ignored once latched. Route invalid/phone call → `INTERRUPTED`; dead recorder → `ERROR_RECOVERY`. No speech-to-text of room conversations. |
| `COMMAND_LISTENING` | KWS suppressed; ASR consumes replay then live PCM, or exclusive one-shot input. Endpoint + nonempty final → `PROCESSING` once. Initial no-speech 7 s, end silence ~1.3 s, hard cap 20 s, optional follow-up 6 s (baseline values, tune); no complete utterance → discard, return to idle mode. Use early accept only for complete low-risk grammar; never execute an ambiguous prefix or a truncated call. |
| `PROCESSING` | One accepted final; classify locally, check policy, execute on worker. No idle ASR; retain capture only for enabled and tested interruption/next wake on the same stream. Need confirmation → `SPEAKING` with a bound question, then `COMMAND_LISTENING` **for that answer only**. Result/deltas → `SPEAKING`, no response needed → idle mode. Default 30 s turn deadline; separately bounded user-approved multi-step work (e.g. 60 s/8 steps). On timeout cancel, report any already dispatched effect, never retry it. |
| `SPEAKING` | One output ticket/focus lease; mute KWS/flush stale pre-roll during normal playback. Optional opt-in barge-in uses the same PCM + existing AEC/echo comparator only on verified routes; if unreliable use button/Stop, not a second recorder. Barge-in cancels output, new turn → `COMMAND_LISTENING`; natural completion → pending approval answer, bounded optional follow-up, or idle. Silence/generation mismatch cannot approve. Stream stall → stop/fallback locally without duplicating already spoken sentences; total output deadline proportional to reply with a hard cap (initially 60 s). |
| `INTERRUPTED` | Known blocker: call, privacy mute, role-session loss, focus/input/route preemption. Revoke turn, abort partials/approvals, stop playback, yield capture and owned routing. Resume only on relevant cleared condition, same consent and legal context; fresh ring/turn, never replay old work. If prolonged or no observable recovery, drop FGS and offer explicit re-arm. |
| `ERROR_RECOVERY` | Classify permission/model, policy or transient hardware errors. Missing/revoked permission, corrupt model, illegal start or exhausted retries → no capture, actionable UI → `DISABLED`. Only transient errors get the bounded attempt schedule in §3; success returns to verified idle/Talk retry, not a half-finished command. |

“Idle mode” means `WAKE_LISTENING` only with live authorized standby; otherwise `DISABLED` and stop the one-shot FGS. **Any state + Off** persists off first, increments generation, cancels work and timers, flushes capture buffers, stops/destroys external recognizer, releases recorder/native streams after their reader exits, releases focus/mode/route/callbacks, stops playback and removes FGS notification. Model-load, ASR, network, permission-result and TTS callbacks carry generation/turn IDs; stale callbacks cannot reopen audio. Device/call events outrank recognition. Cancel/timeout/session dismissal releases waiters (including `host.ask`/speech completion) without blocking the main thread. Use elapsed realtime and check deadlines after sleep as well as in timers.

Deduplicate `hit + headset + session` by active turn; accept ASR final once by `(generation, turnId)`. Existing `TaskBoard.duplicateOf` 1.2 s text window is secondary, not an execution guarantee. Mark each irreversible step dispatched **before** issuing the platform operation; uncertain outcome means “requested, not verified,” no replay after crash/cancel. A later intentional repeat needs a new turn and confirmation. During processing, an explicit new turn cancels uncommitted work and invalidates approval; it cannot undo a placed call or already sent message.

## 7. Command execution, permissions and data boundaries

Route local `TaskControl`/corrections, memory intents and `router/FastCommandRouter.kt` before AI. Separate parse → typed action proposal → policy/authorization → execution → observed outcome. Enforce the same gate immediately **before** effect dispatch from fast router, accessibility tools and any AI planner. A spoken keyword or recognized “yes” is not authentication. Under keyguard allow only a narrow user-configured nonpersonal set (initially time and media transport); defer personal results, contacts, app UI, text entry and all consequential actions to unlocked, user-visible context. Offer notification/normal OS unlock; if using `KeyguardManager.requestDismissKeyguard` from a visible activity, verify unlocked on completion, deny on cancel/timeout. Remove bright wake lock/poll-through behavior. Never read or tap a credential challenge.

| User intent | Primary action and safe fallback |
|---|---|
| Call a contact/number | Local `contacts/ContactResolver.kt` with just-in-time `READ_CONTACTS`; resolve identity and phone type/number, prompt if multiple plausible matches or numbers. Default `ACTION_DIAL` with encoded `tel:` URI and user places call. Optional direct `ACTION_CALL` only for a valid ordinary number, unlocked, explicit one-use confirmation of person/number, granted `CALL_PHONE` and allowed activity launch. Unknown, emergency, service/USSD or malformed number: never direct-call; emergency requests go to system dialer, no automatic submit. Missing permission → dial/choose in UI. `READ_PHONE_STATE` optional, not needed for KWS; `TelecomManager.isInCall` cannot establish that the named party answered. Hand call routing to Telecom, yield mic. Never test by dialing live emergency numbers. |
| Music | Map “pause”, “resume”, “next”, “previous”, “play X [on Y]” locally; resolve Stop-vs-stop-speaking by state. For an identified player prefer supported `MediaController.TransportControls` and capability flags; `playFromSearch` or `MediaStore.INTENT_ACTION_MEDIA_PLAY_FROM_SEARCH` if handled. `MediaSessionManager.getActiveSessions(component)` requires an **enabled** notification listener for ordinary Ash; separate disclosure/opt-in, minimal processing, ignore Ash sessions, ask among ambiguous players. Never request privileged `MEDIA_CONTENT_CONTROL`. Without access use supported intent or existing global media-key fallback for untargeted transport; don't claim a particular track/player changed without evidence. No YouTube scraping to bypass an unsupported search. |
| Open app / navigate | Match installed launchable apps with existing `router/AppMatcher.kt` and launcher queries; use package launch intent, or supported scoped `ACTION_VIEW` (`geo:` for maps). Disambiguate names/handlers, handle unavailable/denied launches. Don't start arbitrary intent URIs from model text. Prefer native intents over driving UI. |
| Scroll / enter text / read screen | Only after separate disclosure and user enabling `JarvisAccessibilityService` in Settings. Use public node actions/global actions on current allowed package/window; verify foreground window again before each step. `ACTION_SET_TEXT` only for requested editable non-secret field; Enter/submit is a **separate effect**. Prefer local node text to screenshots. Deny payment, authentication, password/OTP, secure or unknown sensitive UI; unavailable nodes or blocked screenshots mean stop, not a coordinate fallback. No accessibility dependency for wake, dialing or media intent. |
| AI multi-step | A model may suggest a bounded plan, not authorize it. Allowlisted structured actions, typed arguments, per-step foreground/package checks, human review, cancellation between steps; treat web/UI/model text as data. For send/call/delete/purchase/share or disclosure bind one-use approval to `(turn, action, target, payload, foreground context, expiry)`; require fresh user confirmation, expire after 10 s/no, re-lock, target change or interruption. For protected financial/auth flows hand control back, even after a “yes”. Unknown consequence (e.g. icon-only coordinate tap, long press, swipe, generic Enter) → refuse/manual step. After execution observe real result or report uncertainty. Never let the model set `userConfirmed`. |

Use the user-visible OS permission flow only for the feature being invoked. `MODIFY_AUDIO_SETTINGS` for communication routing; `BLUETOOTH_CONNECT` runtime on 31+ for protected paired-device/profile APIs only, legacy `BLUETOOTH` through 30 if such APIs used. OS audio-device enumeration is not Bluetooth discovery: no scan/location permission just to route. With denied Nearby Devices continue phone/wired. `BIND_ACCESSIBILITY_SERVICE` and optional `BIND_NOTIFICATION_LISTENER_SERVICE` guard their **services**; users enable them separately. No notification content needed for media controls. No call log, SMS, overlay, root or signature permission. Wearable pairing/role selection and sideload “restricted settings” are user/system decisions; if disabled, degrade rather than automate setup. For Play distribution disable autonomous accessibility planning/execution; human oversight is not a blanket Play exception. Narrow deterministic user commands require appropriate disclosures, declarations and policy review; don't claim `isAccessibilityTool` for a general assistant. Sideloading does not remove OS or consent boundaries.

Sources: [common Android intents](https://developer.android.com/guide/components/intents-common), [MediaSessionManager](https://developer.android.com/reference/android/media/session/MediaSessionManager), [keyguard](https://developer.android.com/reference/android/app/KeyguardManager), [accessibility service](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService), [Play automation policy](https://support.google.com/googleplay/android-developer/answer/10964491?hl=en).

## 8. Latency, battery and privacy budgets

- **Hot path:** blocking audio reads, bounded reusable PCM slots/ring with explicit lifetime until replay finishes; avoid per-read `FloatArray`, `Pair`, copied lists, asset parsing or file writes in steady state. Keep KWS single-threaded initially; ASR decodes only during a turn. Cache tokenization, time stamp sample positions, measure smaller read sizes against CPU before adopting. No idle focus, ASR rescans, wake polling or repeated model initialization. Trim unused Kokoro/local LLM under pressure; only initialize AI/TTS when routing requires them, not at every wake. Keep small KWS and, for seamless mode, ASR resident while armed; if resources insufficient show limited mode.
- **Routing:** fast commands work after provisioning with airplane mode on. Use `ai/AiRouter.kt` / `ai/RoutePolicy.kt` for complex questions, not simple commands or all failures. Installed embedded model if permitted; cloud only with user-selected provider, key, permitted data scope and connectivity. Cloud unavailable → local model/intent if capable; otherwise say what couldn't be done. Never retry a side effect through a different provider. No OMP account/subscription as a runtime entitlement.
- **Streaming:** use `agent/OpenAiCompatibleSession.kt` text deltas → bounded sentence queue → existing `ReplyStreamer`/`Speaker`; cap queued speech, start first sentence before full answer. For providers without true streaming, report it as buffered. `agent/AnthropicSession.kt` inherits default cancellation/buffered delivery: implement actual provider cancellation before enabling it for interruptible work; always suppress stale callbacks. Stop/replace cancels network/native generation where supported, pending TTS, playback and any approval. No queued effect may commit after cancel.
- **Boundaries:** idle and pre-roll PCM is volatile and local only. Never put it in logs, crash attachments, task history, disk caches, platform recognizer or cloud. Default on-device command ASR/TTS; remote LLM receives only explicitly permitted post-wake text. Cloud TTS also discloses reply text; opt in separately. Screen/contacts/history are not implicit prompt context; redact and obtain per-feature consent, keep sensitive content on device, disable unneeded capture. Show coarse state on a locked display. Replace transcript-bearing logs/echo diagnostics and bound or disable personal task history/cache by default; support deletion. Record only event enum, route class, coarse failure code, counts and monotonic durations (see `util/LatencyTrace.kt`). No raw audio, transcript, number, screen contents, BT identifier, endpoint secret or tool arguments in telemetry.
- **Secrets and downloads:** use [Android Keystore](https://developer.android.com/privacy-and-security/keystore) for a nonexportable AES-GCM key; store ciphertext, fresh IV and version in app-private storage. Migrate all provider/TTS/legacy preference keys on explicit unlocked setup, verify readback then delete plaintext, reset/re-enter on invalidation; never bake keys into APK, intents or crash logs. TLS for remote services, limit exceptions to explicitly intended local endpoints (loopback by default), no global cleartext or public redirects with credentials. Verify pinned model digests before extraction/activation, reject incomplete/mismatched vocabularies, preserve last good installation. No download of models while waiting for a wake hit.
